# 曦薇空间 · 数据采集与来源说明

本文说明自动采集的边界、适配器结构、规范化与去重、规则分类、审核策略，以及来源追溯与合规要求。

## 一、原则与边界

- **只接入公开可访问的数据**：公开 RSS 或管理员人工核验录入。
- **不模拟登录、不使用 Cookie 登录、不绕过反爬**。需要登录或存在访问限制的平台不接入自动采集。
- **不将大模型作为采集与分类的强依赖**：分类完全由可审计的关键词规则完成。
- **每个来源独立启停**：停用来源后不会再被调度，不影响其他来源。
- **所有公开内容保留来源**：来源名称、来源 URL、可信等级与采集时间均随内容保存。
- **重要信息人工审核**：命中重要关键词、社区来源、无法分类的内容必须审核通过后才公开。
- **原始数据不对外**：`raw_data` 只在数据库中留存，公共 API 不返回。
- **图片默认不使用第三方素材**：RSS 图片默认不采集，详见 [图片与版权说明](图片与版权说明.md)。

## 二、组件与数据流

```text
cmd/worker
  └─ Worker.Run
       ├─ RecoverStaleJobs / RecoverStaleSearchRuns  按心跳恢复超时任务
       ├─ CreateDueJobs       按 interval_minutes 生成到期 RSS 任务
       ├─ CreateDueSearchRuns 按 interval_minutes 生成到期搜索任务
       ├─ ClaimJob            FOR UPDATE SKIP LOCKED，最多并发 2 个
       │    └─ Processor.Run（RSS / 人工）
       │         ├─ 每 30 秒刷新 heartbeat_at
       │         ├─ NewAdapter(source) ── adapter.Fetch(ctx)
       │         ├─ ListRules → Classify → DecideReview → InferContentType
       │         └─ InsertCollected（来源条目 ID → URL → 内容指纹）
       └─ ClaimSearchRun      与 RSS 任务共享并发额度
            └─ SearchProcessor.Run
                 ├─ 每 30 秒刷新 heartbeat_at
                 ├─ SearchProvider.Search     Bing RSS / SearXNG
                 ├─ ValidatePublicURL         SSRF 校验
                 ├─ MetadataFetcher.Fetch     公开页面元数据
                 ├─ Classify / InferContentType
                 └─ InsertDiscovered          候选入库，默认待审核
```

- Worker 每 30 秒执行一次调度与领取。每次领取在采集与搜索之间交替优先，任一队列为空时自动回退到另一类，避免一类任务长期饥饿。
- 单来源同时只允许一个活动任务（数据库部分唯一索引保证）；搜索任务同理。
- 单个任务执行上下文为 3 分钟；执行中每 30 秒写入心跳。心跳超过 8 分钟（采集）/ 10 分钟（搜索）未更新时，任务被标记为失败并记录「心跳超时」，避免误回收仍在运行的任务。
- 终态为 `success` / `partial` / `failed`：部分条目或候选处理失败时记为 `partial`，不会把部分失败显示为成功。
- 任务记录抓取、新增、去重、失败、元数据解析计数与错误摘要，便于管理端排查。
- Worker 启动时记录版本、调度间隔、并发上限；日志包含 `worker_id`、`task_type`、任务 ID、耗时、计数与错误，不输出数据库口令或密钥。

## 三、SourceAdapter 抽象

```go
type SourceAdapter interface {
    Name() string
    Validate() error
    Fetch(ctx context.Context, cursor string) ([]RawItem, string, error)
}
```

当前实现：

| 适配器 | 用途 | 行为 |
| --- | --- | --- |
| `rss` | 公开 RSS / Atom | 使用 gofeed 拉取，按关键词过滤，最多 100 条 |
| `manual` | 人工来源 | 不自动抓取，仅记录核验入口与备注 |

`RawItem` 包含来源条目 ID、标题、摘要、URL、封面、作者、发布时间与原始 JSON。适配器只负责获取与初步清洗，不直接写数据库。

### 新增适配器

1. 在 `backend/internal/collector/` 实现上述接口；
2. 在 `NewAdapter` 中注册 `adapter_type`；
3. 在管理端来源类型校验中加入新类型；
4. 增加单元测试，确认只访问公开接口、不携带登录态、不绕过访问控制；
5. 更新本文档与部署配置。

不要把平台密钥写入前端；需要密钥的适配器应由后端环境变量或来源配置注入，并在管理端掩码显示。

## 四、SearchProvider 搜索抽象

搜索与 RSS 采集是两条独立链路。搜索任务不伪装成 RSS 来源，也不要求 RSS 适配器承担搜索职责。

```go
type SearchProvider interface {
    Name() string
    Validate() error
    Search(ctx context.Context, req SearchRequest) ([]SearchResult, error)
}
```

`SearchRequest` 包含关键词、限定域名、时间窗口、页码与单页数量。当前实现：

| 服务类型 | 说明 | 密钥 | 限制 |
| --- | --- | --- | --- |
| `bing_rss` | 必应网页搜索 RSS，`format=rss`，无需密钥 | 无 | 受必应服务条款约束，仅限个人非商业 RSS 聚合；结果数量与排序由服务端决定 |
| `searxng` | 自建 SearXNG JSON API，可配置实例地址 | 可选，通过环境变量引用 | 需要自行部署并遵守实例与上游搜索引擎条款 |

搜索任务字段：名称、搜索服务、关键词、限定站点（最多 10 个）、内容分类提示、来源类型、可信等级、运行间隔（≥ 15 分钟）、单次最大结果数（1–50）、启停、上次 / 下次运行、成功 / 失败原因。

- 搜索服务 API Key **只保存环境变量名**（如 `SEARXNG_API_KEY`），不保存密钥值；接口配置中出现 `api_key`、`token`、`password`、`secret` 等字段会被拒绝。
- 管理端「连接测试」执行真实查询并记录延迟与结果数，不返回密钥。
- 搜索运行与 RSS 任务共享 Worker 并发额度，单个任务只允许一个活动运行。
- 搜索结果全部写入候选池（`review_status=pending`、`content_status=pending`），必须人工审核后才公开。
- 搜索候选仅按规范化 URL 去重，不按标题 + 摘要指纹合并，避免把不同媒体的独立报道或不同图集合成一条。

## 五、Web Metadata Adapter

对通过 SSRF 校验的搜索结果 URL 尝试读取公开页面元数据：

- 标题：`<title>`、`og:title`、`twitter:title`、JSON-LD `headline`；
- 摘要：`meta description`、`og:description`；
- 作者：`author`、`article:author`、JSON-LD `author`；
- 发布时间：`article:published_time`、`datePublished`、常见时间 meta；
- 规范链接与封面链接：仅解析地址并记录在 `raw_data`，**不下载图片，也不自动作为站内封面**。

失败处理：登录页 / 验证码 / 安全验证识别为 `blocked`，HTTP 403 / 429 等识别为 `blocked` 或 `failed`。失败时仍保留搜索标题、搜索摘要与原始链接，后台标记解析状态与错误，不把搜索摘要伪装成原文全文。

安全限制：仅 `http` / `https`；拒绝账号密码、非 80 / 443 端口、内网 / 回环 / 链路本地 / 云元数据地址；DNS 解析在拨号阶段再次校验，防止 DNS 重绑定；最多 3 次重定向；响应体上限 2 MB；总超时 15 秒；不携带 Cookie 或登录态。

## 六、RSS 来源配置

```json
{
  "feed_url": "https://example.com/feed.xml",
  "keywords": ["田曦薇"],
  "use_feed_images": false
}
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `feed_url` | 是 | 仅允许 `http` / `https` 公开地址 |
| `keywords` | 否 | 数组；为空接收全部条目，非空时标题 / 摘要 / 正文任一命中即收录 |
| `use_feed_images` | 否 | 默认 `false`；仅在确认图片授权后开启 |

采集请求使用固定 User-Agent：`XiweiSpaceBot/1.0 (+public RSS reader; contact: site administrator)`，超时 25 秒。适配器会遵循重定向，但不携带任何浏览器 Cookie 或登录凭证。

## 七、规范化

每个条目入库前执行：

1. 去除 HTML 标签、`script`、`style`，合并空白；
2. 标题截断至 300 个字符，摘要截断至 1200 个字符；
3. URL 规范化：小写协议与主机、移除 fragment、移除 `utm_*` / `spm` / `from` / `share_token` / `scene` 参数、去除末尾 `/`；
4. 发布时间缺失或晚于当前时间 24 小时以上时保持 `NULL`，精度记为 `unknown`，**不会把发现 / 采集时间写成发布时间**；
5. `discovered_at` 记录首次发现时间，`collected_at` 记录本次写入时间，两者与 `published_at` 分离；
6. 作者为空时使用来源名称；
7. 基于规范化 URL 计算 SHA-256，基于标题 + 摘要计算内容指纹。

## 八、去重策略

按顺序检查，任一层命中即视为重复并跳过：

1. **来源条目 ID**：`(source_id, source_item_id)` 唯一；缺失时使用条目 URL；
2. **规范化 URL**：`url_hash` 全局唯一；
3. **内容指纹**：`content_hash` 在最近 **14 天** 内重复即视为重复（标题 + 摘要完全一致）。

并发写入时数据库唯一索引兜底；唯一冲突会被识别为重复而不是失败。相同内容在不同来源、不同链接下仍可能被判为指纹重复，这是刻意的降噪策略。

搜索候选只做规范化 URL 去重：不同媒体对同一事件的独立报道应分别保留，不能因为标题相近而合并；同一图集的不同分页也按各自 URL 保留。

## 九、规则分类

分类不调用外部模型，依据 `classification_rules` 表中的关键词：

| 场景 | 默认关键词（种子） |
| --- | --- |
| 剧粉 | 剧集、角色、开播、定档、杀青、开机、预告、花絮、剧照、电视剧、影视 |
| 颜值粉 | 写真、杂志、造型、妆造、自拍、美图、大片、封面 |
| 综艺粉 | 综艺、节目、真人秀、采访、访谈 |
| 日常粉 | 日常、生活、分享、微博、自拍 |
| 时尚商务粉 | 品牌、代言、商务、时尚、合作、大使 |
| 事业粉 | 作品、官宣、开机、杀青、荣誉、获奖、票房、收视、进组 |
| 活动粉 | 活动、发布会、见面会、红毯、盛典、路演 |

- 匹配不区分大小写；关键词可用中英文逗号、顿号、分号、空格或换行分隔。
- 一条内容可命中多个场景，全部保留。
- 规则可在管理端增删改、调整优先级与启停；停用规则不参与分类。
- 未命中任何规则的内容会进入待审核，由管理员归类。

### 内容类型推断

在场景分类之外，还会根据文本推断独立于饭圈场景的内容类型：新闻资讯、社交帖子、图片、视频、采访、官方公告、作品信息、活动信息等。完整类型包括 `news`、`post`、`social`、`image`、`video`、`interview`、`official`、`work`、`event`、`drama`、`variety`、`fashion`、`media`、`topic`、`internal`、`other`。内容类型只影响展示分类，不改变审核结论。

### 时间字段与精度

| 字段 | 含义 |
| --- | --- |
| `published_at` | 原始发布时间；不可信或缺失时为 `NULL` |
| `published_precision` | `verified`（页面明确给出）/ `estimated`（仅搜索摘要给出）/ `unknown` |
| `discovered_at` | 首次发现该条目的时间 |
| `collected_at` / `created_at` | 本次采集写入 / 入库时间 |

前台主时间线排序为 `COALESCE(published_at, discovered_at) DESC, created_at DESC, id DESC`，分页使用包含有效时间、创建时间与 ID 的游标，避免 offset 翻页在新增内容时重复或遗漏。事件关联不修改上述任何时间字段。

## 十、可信等级与官方标记

可信等级沿用来源配置：`official`、`media`、`reference`、`community` 等。来源类型为 `official` 或可信等级为 `official` 时，内容会标记为官方。可信等级参与推荐权重与审核判定，不替代人工核验。

## 十一、审核判定

| 条件 | 审核状态 | 内容状态 | 原因 |
| --- | --- | --- | --- |
| 命中重要信息关键词 | `pending` | `reviewing` | 涉及重要信息「…」，发布前需人工核验 |
| 来源类型 / 可信等级为社区 | `pending` | `reviewing` | 来源为社区内容，需人工核验 |
| 未命中任何场景规则 | `pending` | `reviewing` | 内容分类不确定，需人工归类 |
| 其他 | `none` | `published` | 自动发布 |

重要关键词包括：官宣、定档、开机、杀青、获奖、荣誉、恋情、声明、律师函、代言、发布会、封面、争议、道歉、解约、签约、结婚、婚讯、去世、讣告、番位、票房、收视、起诉、风波等。

管理员可随时在「内容管理」中调整状态。被驳回的内容公共 API 返回 404，不会出现在列表、推荐或收藏展示中。

## 十二、来源追溯与原始数据

- 每条内容保存来源信息：RSS 使用 `source_id`，搜索候选使用可空的 `source_id` 加上 `origin_name`、`origin_platform`、`origin_type` 与 `search_task_id`，保证来源可追溯。
- 内容详情页展示来源名称 / 平台、原始链接、发布时间精度、发现时间与可信等级，用户可回到原始公开页面核验。
- `raw_data` 保存适配器原始 JSON，以及搜索候选的搜索标题 / 摘要 / 引擎时间、元数据解析状态与错误；仅供后台审核追查。
- 公共接口在序列化前移除 `raw_data`；管理端只在内容编辑弹窗的折叠区展示采集原始数据。
- 来源与搜索服务密钥不进入前端；搜索服务只保存环境变量名，API 不返回密钥值。

### 事件关联

事件（`events`）通过 `content_events` 与内容多对多关联，用于聚合公开活动、作品节点或采访。事件只影响详情页与事件页聚合，不改变内容发布时间、审核状态或主时间线。删除事件只删除关联，不删除内容。

## 十三、种子来源

种子数据包含 6 个来源，均记录公开参考地址：

| 来源 | 类型 | 适配器 | 默认状态 | 说明 |
| --- | --- | --- | --- | --- |
| 必应新闻 · 田曦薇 | 媒体 | RSS | 启用 | 公开新闻 RSS；端点可用性取决于部署网络 |
| 百度百科 · 田曦薇 | 参考资料 | 人工 | 启用 | 用于人工核验基础资料 |
| 豆瓣 · 作品资料 | 参考资料 | 人工 | 启用 | 用于人工核验作品与角色 |
| 微博 · 官方账号 | 官方 | 人工 | 停用 | 需先核验官方账号地址 |
| 品牌与活动官方渠道 | 官方 | 人工 | 停用 | 人工核验后录入 |
| 小红书 / 抖音 · 授权链接 | 社区 | 人工 | 停用 | 仅接入获得授权的公开链接 |

人工来源不会自动抓取。RSS 来源如果返回 HTML、登录页或反爬页面，任务会记录 `fetch RSS: failed to detect feed type` 并保持失败状态，不会写入不可信内容。管理员应核对地址后替换为公开可用的 RSS，或改为人工来源。

搜索种子包含「必应网页搜索 RSS」服务与两个搜索任务（综合资讯、作品与采访），首次启动时写入，可在管理端修改或停用。种子任务每 6 / 12 小时运行一次，结果全部进入待审核候选池。

### 实际覆盖与限制

| 渠道 | 覆盖情况 | 限制 |
| --- | --- | --- |
| 新闻 / 媒体网站 | 较好 | 取决于必应索引与站点是否允许读取；部分站点返回 403 / 登录页 |
| 百科 / 资料站 | 较好 | 百度百科常返回 403，仍保留搜索摘要与链接 |
| 微博 / 小红书 / 抖音 | 有限 | 页面通常要求登录或验证码，自动解析会被标记 `blocked`；不绕过平台限制 |
| 视频平台 | 有限 | 可获取搜索摘要，播放页元数据可能不完整 |
| RSS | 取决于配置 | 原种子「必应新闻 RSS」在部分网络已不再返回 XML，需替换或停用 |

搜索引擎摘要中的日期通常代表索引或抓取时间，不能等同于原文发布时间，因此只标记为 `estimated`。需要精确时间时必须由管理员在原文核验后修正为 `verified` 或清空为 `unknown`。

## 十四、合规检查清单

- [ ] 采集与搜索地址公开可访问，无需登录、Cookie、验证码或绕过访问控制
- [ ] 未使用平台密钥，或密钥仅通过后端环境变量引用、未写入数据库 / 前端
- [ ] 搜索服务与任务符合其服务条款；必应 RSS 未用于商业再分发（除非已获书面许可）
- [ ] 来源与搜索任务已启用且间隔合理，未对目标站点造成高频请求
- [ ] 自动发布内容分类明确、来源可信
- [ ] 重要信息、社区内容、未分类内容与全部搜索候选均经人工审核
- [ ] 发布时间精度正确，未知时间未被伪造成发布时间
- [ ] 图片未在未授权情况下采集或展示
- [ ] 来源链接保留且可访问，可回溯核验
- [ ] 失败任务已处理，未通过编造数据填充页面
