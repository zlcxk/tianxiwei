# 曦薇空间 · 管理指南

本文面向站点管理员，覆盖初始化、日常审核、数据源与基础资料维护。采集原理与合规要求见 [数据采集与来源说明](数据采集与来源.md)。

## 一、首次初始化

1. 部署完成后打开 `http://<站点地址>/setup`。
2. 填写管理员邮箱、昵称与密码（至少 10 位）。
3. 提交后自动登录并进入 `/admin`。

初始化接口只在 `users` 表为空时成功；站点已初始化后访问 `/setup` 会被重定向。系统没有默认账号或固定密码。请妥善保存管理员凭据，并在稳定后关闭访客注册（`ALLOW_REGISTRATION=false`）。

## 二、后台导航

| 页面 | 用途 |
| --- | --- |
| 管理概览 | 今日采集 / 入库、待审核、来源异常、成功率、最近任务 |
| 内容管理 | 检索所有内容与搜索候选、修正发布时间、编辑状态与关联关系 |
| 待审核 | 审核重要信息、社区内容、未分类内容与全部搜索候选 |
| 内容发现 | 搜索服务与搜索任务管理、连接测试、立即搜索、运行记录 |
| 事件管理 | 创建 / 编辑 / 归档事件，预览事件页 |
| 编辑精选 | 从已发布内容中挑选首页展示条目，配置顺序、展示时间与启停 |
| 数据源 | 新建 / 编辑 RSS 或人工来源、启停、立即运行 |
| 采集任务 | 查看任务状态、计数、错误、重试失败任务 |
| 基础资料 | 艺人、人物实体、作品、角色、场景、分类规则、推荐权重 |

后台使用与前台一致的编辑式视觉，不是传统 B 端表格风格；移动端同样可用。

## 三、日常审核流程

1. 打开「待审核」，查看待审内容标题、来源、分类与审核原因。
2. 在原文 / 来源链接中核验信息（尤其是官宣、定档、获奖、恋情、声明、代言等重要信息）。
3. 选择：
   - **通过**：内容变为 `published`，进入公开内容流；
   - **驳回**：填写原因后变为 `rejected`，公共 API 不再返回。
4. 审核原因会保留在内容记录中，便于追溯。

以下情况会被自动送入待审核：

- 标题或摘要命中重要信息关键词（官宣、定档、开机、获奖、代言、声明等）；
- 来源类型或可信等级为社区内容；
- 未命中任何分类规则，无法确定场景。

其他内容在分类明确、来源可信时自动发布。管理员仍可在「内容管理」中随时调整状态。

## 四、内容管理

### 手动录入

点击「新建内容」，填写：

- 标题、摘要、内容类型、可信等级；
- 来源名称与来源 URL（建议填写可核验的公开链接）；
- 发布时间、是否官方；
- 场景、关联作品、关联角色；
- 封面 URL（仅在确认拥有展示授权时填写）。

手动录入默认审核通过并发布，因为这是管理员主动编辑的行为。请仍遵守来源与版权要求。

### 编辑内容

可修改标题、摘要、类型、来源链接、封面、官方标记、可信等级、发布 / 审核状态、审核说明，以及事件 / 作品 / 角色关联。编辑弹窗还可以：

- 修正 **原始发布时间** 与时间精度（`verified` / `estimated` / `unknown`）；
- 勾选「来源没有可靠发布时间」清空 `published_at`，此时前台按发现时间排序并标注「时间未知」；
- 在折叠区查看采集原始数据与元数据解析结果，包括搜索标题 / 摘要、解析状态和错误。

原始抓取数据只保存在数据库，不在公共 API 与前台展示。

搜索候选筛选：在内容管理勾选「仅搜索候选」，或按发布状态 / 审核状态 / 元数据解析状态 / 相关度 / 过滤原因筛选。候选默认处于 `pending`，需人工核验标题、摘要、时间和来源后再通过。若页面被登录页或验证码拦截，候选仍会保留搜索摘要与原始链接，不会自动补全正文。

自动过滤与低置信候选：低于 40 分的搜索结果会区分两种情况。姓氏 / 字典内容、实体指向不明确、与人物无关等**明确无关**结果标记为 `rejected` 并写入 `filter_reason`；页面被拦截、摘要过短或缺少上下文的**低置信**结果保留 `pending`，进入待审核队列，原因标记为「上下文不足」。两类内容都可在「内容管理」中按相关度与过滤原因查看，用于复查误过滤。

## 五、数据源管理

每个来源可独立启停，停用后不会再被调度。支持两类：

- **RSS 自动采集**：配置 `feed_url`，可选关键词过滤 `keywords`（数组）与 `use_feed_images`；
- **人工来源**：仅作为核验入口记录，不自动抓取，由管理员手动录入内容。

「立即运行」会创建一个手动任务，由 Worker 异步执行。同一来源同时只允许一个活动任务；若已有任务在排队或执行，新的触发会复用 / 拒绝重复任务。

### RSS 配置示例

```json
{
  "feed_url": "https://example.com/feed.xml",
  "keywords": ["田曦薇"],
  "use_feed_images": false
}
```

- `keywords` 为空时接收全部条目；非空时标题 / 摘要 / 正文中任一命中即收录。
- `use_feed_images` 默认 `false`。只有确认图片授权后才可设为 `true`；否则采集内容不保存第三方图片地址。
- 仅填写公开可访问的 RSS 地址。不要配置需要登录、模拟 Cookie 或绕过反爬的接口。

种子中的「必应新闻 · 田曦薇」使用公开 RSS 端点，但该端点可能因网络或站点策略返回 HTML / 重定向。此时任务会显示 `fetch RSS: failed to detect feed type`。处理方式：

1. 在浏览器或 `curl` 中确认该地址是否返回 XML；
2. 更换为当前网络可访问的公开 RSS；
3. 或停用该来源，改用人工来源录入。

失败不会影响其他来源，也不会写入不完整内容。

## 六、内容发现（搜索服务与任务）

「内容发现」页面分三部分：

1. **搜索服务**：名称、类型（必应网页搜索 RSS / SearXNG）、地址、启用状态、连接测试与最近测试结果。
2. **搜索任务**：关键词、限定站点、内容分类提示、来源类型、可信等级、运行间隔、单次上限、上次 / 下次运行、失败原因。
3. **最近搜索记录**：状态（排队中 / 搜索中 / 成功 / 部分成功 / 失败）、开始与结束时间、耗时、抓取、新增、重复、失败、元数据解析成功 / 失败计数与错误摘要。部分成功表示搜索本身完成，但少数结果处理失败。

### 添加搜索服务

- 必应 RSS：默认地址 `https://www.bing.com/search`，无需密钥。
- SearXNG：填写自建实例地址；如实例启用鉴权，把密钥写入 API / Worker 进程的环境变量（例如 `SEARXNG_API_KEY`），然后在「API Key 环境变量名」填写该变量名。系统只保存变量名，不保存、也不返回密钥值。
- 配置中若出现 `api_key`、`token`、`password`、`secret` 等密钥字段，保存会被拒绝。
- 「连接测试」会执行一次真实查询，记录延迟与结果数；测试失败不会自动停用服务。

### 搜索任务

- 关键词必须包含完整人物姓名或已验证别名；只用「田」「演员」等泛词会被拒绝。
- 搜索间隔最少 15 分钟，单次最多 50 条，限定站点最多 10 个。
- 「立即搜索」只把任务加入队列，由 Worker 异步执行；同一任务同时只允许一个活动运行。
- 搜索结果按人物相关性打分：标题含姓名 +40、摘要含姓名 +25、已验证账号 +25、关联作品 / 角色 / 事件每项 +15。≥70 为高度相关，40–69 为候选；低于 40 分时，明确无关的自动过滤，上下文不足的作为低置信候选进入待审核。
- 已验证账号只做账号全名精确匹配，且不再使用来源名称 / 平台名做包含判断。建议写成 `平台:账号`（如 `weibo:田曦薇`），此时还要求结果来自同一平台。
- 未被过滤的结果进入候选池，不会自动公开。到「内容管理」勾选「仅搜索候选」审核，或直接在「待审核」处理。
- 内容类型优先按实际结果中的标题 / 摘要 / 平台特征判断，任务的内容分类提示只在结果没有信号时兜底。
- 若出现误过滤（例如只用了已核验昵称），先在「基础资料 → 人物实体」补充别名，再重新运行任务。
- 页面被登录 / 验证码 / 反爬拦截时，候选标记为 `blocked`，保留搜索摘要和原始链接；不要尝试通过配置 Cookie 或模拟登录绕过。
- 第一页搜索失败时运行记为失败；后续页失败时记为部分成功，运行记录会写明失败页码与原因。只有完整成功的运行会推进「上次成功」时间，并作为下一次 7 天重叠窗口的基准（可用 `SEARCH_OVERLAP_DAYS` 调整）。
- 任务级「可信等级」不会把任意站点标记为官方；每条结果的可信等级与官方标识按实际发布域名判定。

### 必应 RSS 条款

必应 RSS 结果受 Microsoft 服务条款限制。未获得书面许可时，仅用于个人、非商业的 RSS 聚合；正式商用或再分发前请自行确认授权。搜索结果数量与排序由必应决定，本站无法保证覆盖完整。

## 七、采集任务

- 任务状态：排队中、采集中、成功、部分成功、失败；部分成功表示任务完成但有条目处理失败，失败任务可「重试」，会新建一条关联任务。
- 计数：抓取条目、新增、去重、失败条目；错误信息显示在任务卡片内。
- 单个来源的调度间隔由来源的 `interval_minutes` 决定；Worker 每 30 秒检查一次待执行任务，采集与搜索任务交替优先领取，避免一类任务长期占用调度资源。
- 页面每 15 秒自动刷新，可手动关闭自动刷新。
- 任务执行上下文为 3 分钟；执行中的任务每 30 秒写入一次心跳。超过 8 分钟（采集）/ 10 分钟（搜索）没有心跳的运行中任务，会被 Worker 标记为失败并记录「心跳超时」，不会误回收仍在正常执行的任务。
- 只会展示最近 100 条任务。

### 任务长期排队排查

1. 先确认 Worker 容器真的在运行：`docker compose ps -a`，并查看 `docker compose logs --tail=200 worker`。
2. Worker 启动日志应包含 `collection worker started`、`worker_id`、`version`、`tick_interval`、`max_concurrent`。
3. 如果 Worker 日志显示的是 API 启动信息，说明容器命令配置错误：镜像必须使用 `CMD` 而不是 `ENTRYPOINT`，否则 worker 服务会执行 API。修复后执行 `docker compose up -d --build`。
4. 检查数据库 `collection_jobs` / `search_runs` 中是否长期存在 `queued` 或 `running` 任务；运行中任务可查看 `started_at`、`heartbeat_at`。
5. 查看 Worker 日志中的 `claim job failed`、`schedule jobs`、`database connection failed` 等错误；数据库短暂不可用时 Worker 会持续重试，恢复后自动继续调度。
6. 搜索任务还需确认 Provider 已启用、搜索任务已启用、`next_run_at` 已到期。

## 八、事件管理

事件用于把同一公开活动、作品节点或采访的多条内容聚合到一个页面。

1. 在「事件管理」新建事件，填写标题、说明、日期、地点与状态；
2. 初始为「草稿」，核验后改为「已公开」；
3. 到「内容管理」编辑内容，在「关联事件」中选择事件；
4. 已公开事件的前台地址为 `/events/<id>`，内容详情页也会显示事件入口。

注意：

- 事件只做聚合，不会改内容的 `published_at`、`discovered_at` 或主时间线顺序；
- 删除事件只解除关联，不删除内容；
- 草稿 / 归档事件对普通用户不可见（管理员与编辑仍可预览）。

## 九、编辑精选

首页「本周精选」由管理员从已发布内容中选择。精选只保存展示信息与关联关系，不复制内容，也不改变原始发布时间。

1. 打开「编辑精选」，点击「新建精选」；
2. 搜索并选择一条已发布内容；待审核、已驳回内容不可选；
3. 可选填写标题、简短描述与封面，留空时使用内容自身信息。封面仅在确认拥有展示授权时填写；
4. 设置展示顺序（数字越小越靠前）、展示开始 / 结束时间与启用状态；
5. 保存后，同时满足以下条件的精选才会出现在首页：已启用、当前时间在展示窗口内、关联内容仍为已发布。

同一内容只能建立一条精选。删除精选只删除展示配置，不会删除内容；内容被删除时，对应精选自动移除。首页没有可用精选时会隐藏该模块，不显示空白占位。

## 十、基础资料

- **艺人**：姓名、英文名、简介、结构化资料（出生日期、出生地、院校、职业、出道年份、来源 URL、核验日期）。
- **人物实体**：完整姓名、已验证别名、已验证账号、排除词。别名与认证账号必须人工核验后填写，系统不会自动推断；验证账号建议使用 `平台:账号` 格式，只接受精确账号匹配；排除词用于拦截姓氏/字典百科页面。
- **作品**：标题、类型、简介、上映日期、状态、平台、官方链接。
- **角色**：所属作品、姓名、简介。
- **场景**：名称、描述、启用状态。停用场景不会出现在前台筛选与偏好中。
- **分类规则**：场景、关键词（逗号 / 顿号 / 空格分隔）、优先级、启用状态。关键词匹配不区分大小写。
- **推荐权重**：场景、时效、可信、热度四项之和必须为 100。热度目前没有可验证信号，实际不参与计算；调整后立即影响推荐排序。

修改基础资料会影响前台展示与关联，请先核验来源。删除作品或角色前确认没有需要保留的关联内容。

## 十一、安全与运维

- API 与 Worker 启动时都会执行数据库迁移，并通过 PostgreSQL advisory lock 串行化，避免并发迁移冲突；两者必须使用同一镜像版本、同一 `DATABASE_URL` 与同一数据库 schema。
- 所有管理接口需要管理员会话与 `X-CSRF-Token`；不要把会话 Cookie 或 CSRF Token 写入前端配置或日志。
- 搜索服务 API Key 只写入服务端环境变量，不要把密钥填入搜索服务配置、备注、日志或仓库。
- 元数据抓取只允许公开 http(s) 页面，并拒绝内网、回环、链路本地、云元数据地址；不要通过来源配置尝试访问内部服务。
- 生产环境通过 HTTPS 提供服务，并设置 `COOKIE_SECURE=true`。
- 数据库不暴露公网；仅通过 Compose 内部网络访问。
- 定期执行 `scripts/backup.sh`，并将备份复制到异地；恢复使用 `scripts/restore.sh <file>`。
- 关注「管理概览」中的来源异常与成功率；连续失败时先检查来源可用性，再决定是否停用。
- 不建议开放访客注册；如确需开放，配合登录限流与人工审核使用。
