# 曦薇空间 · 图片使用与质量说明

本项目不限制图片的使用与版权，也不把授权确认作为上传或引用图片的前置条件。站内图片以**准确、清晰、尺寸合适**为标准：优先使用与艺人、作品、角色、活动严格对应的真实图片，而不是默认用抽象占位图代替；找不到合格图片时才回退到站内 CSS 抽象封面。

站内不设版权审核门槛，不等于图片可以随意错配。使用第三方图片可能涉及著作权、肖像权与平台条款，实际使用范围与风险由站点运营方自行判断并承担。

## 使用原则

1. **准确优先**：图片必须对应正确的人物、作品、角色或活动。宁可暂时留空，也不使用无关图片填充。
2. **质量优先**：使用官方原图或高分辨率公开图；避免低清缩略图、截图、明显二创、严重压缩和带平台水印的图片。
3. **尺寸匹配**：按前台容器比例选择素材。展示时按 `object-fit: cover` 居中裁切，主体应位于画面中部，避免裁掉面部或片名。
4. **全站一致**：同一艺人、作品或角色在各入口使用同一张主图；换图时同步替换头像、封面与海报等入口。
5. **来源可回溯**：保留图片来源链接或上传记录，便于后续核对、替换与撤回。

## 推荐尺寸

| 用途 | 比例 | 建议尺寸 | 说明 |
| --- | --- | --- | --- |
| 艺人头像 | 1:1 | ≥ 800 × 800 | 单人正面，面部清晰 |
| 艺人封面 | 3:4 | ≥ 900 × 1200 | 官方写真或活动图，对应首页主视觉容器 |
| 作品海报 | 3:4 | ≥ 900 × 1200 | 官方海报优先，保留片名与主视觉 |
| 角色头像 | 1:1 | ≥ 600 × 600 | 对应角色的剧照或形象，不复用其他人物 |
| 内容封面 | 16:10 或 3:4 | ≥ 1280 × 800（3:4 时 ≥ 900 × 1200） | 与内容主题一致；列表按方形、详情按 16:10 居中裁切 |
| 事件封面 | 16:9 | ≥ 1200 × 675 | 活动现场图或官方物料 |
| 编辑精选封面 | 16:10 | ≥ 1280 × 800 | 与精选主题一致，首页摘要卡会裁切展示 |
| 收藏 / 列表缩略图 | 取原图 | 沿用主图 | 由主图自动缩放，无需单独准备 |

通用要求：

- 格式为 JPEG、PNG 或 WebP，单张不超过 10MB；
- 画面清晰，避免拉伸变形、过度锐化、明显噪点与大面积压缩色块；
- 不叠加站外水印、二维码或与内容无关的文字；
- 优先使用横竖构图完整的原图，不要直接上传搜索引擎缩略图或聊天软件转发图。

## 图片来源

1. **官方发布**：工作室、艺人账号、剧方、播出平台、杂志与品牌的官方物料。
2. **正规媒体公开物料**：新闻配图、剧照、海报、活动图。
3. **搜索与 RSS 结果中的原文图片地址**：作为候选封面引用，发布前核对是否对应同一人物与事件。
4. **站内 CSS 抽象封面**：没有合格图片时的兜底，不占用图片存储。

## 当前实现

- 项目随包提供一批挑选过的图片，位于 `frontend/public/media/`，通过 `/media/...` 访问；`0010_media_assets.sql` 只在字段为空时写入这些路径，不会覆盖管理员后续上传或修改的图片。
- 随包图片覆盖艺人头像 / 封面、20 部作品的海报、9 个可核实的角色头像，以及主要作品档案、角色档案、GRAZIA、Gucci、生日与成长档案等内容的封面。其余角色头像、活动与杂志封面因无法核实对应关系保持留空。
- 其余图片由管理员上传、填写图片地址，或由搜索结果引用原文图片地址。
- 未设置封面或图片加载失败时，前台封面、作品封面、角色卡与首页主视觉使用 CSS 抽象排版（暖色渐层、细线网格、字母组合与站内文字），由 `CoverArt.vue` 等组件生成。
- RSS 采集默认不保存来源图片地址。管理员可在来源配置中设置 `"use_feed_images": true` 开启；开启后只保存图片地址，不下载、不转存图片。
- 搜索结果的 Web Metadata Adapter 解析页面 `og:image` / `twitter:image`，仅在地址为公开 `http(s)`、非内网、非标准端口时写入候选的 `cover_url`。系统只保存 URL，不下载、不镜像图片。
- 重复搜索结果不会覆盖已有 `cover_url`；管理员手动替换或清空封面后，后续搜索结果也不会改回。
- 管理端可在艺人头像 / 封面、作品封面、角色头像、内容封面、事件封面与编辑精选封面处直接上传图片，或填写图片 URL。
- 上传接口仅限管理员 / 编辑，单张不超过 10MB，仅接受 JPEG、PNG、WebP；服务端按文件内容识别类型，使用随机文件名并存入 `MEDIA_DIR` 持久化目录，前端不可指定存储路径。
- 公共内容接口不返回原始采集数据，但会返回 `cover_url`；前台按该地址展示。
- 「基础资料 → 资料完善」会统计各实体缺失的头像 / 海报 / 封面与图片覆盖率。该面板只提示缺口，不会自动下载、生成或填充图片。

## 运营要求

1. 发布前核对图片与人物、作品、角色、活动是否对应，避免张冠李戴；不确定时先留空。
2. 优先官方高分辨率原图，避免使用搜索引擎缩略图、社交平台二次压缩图与带水印图片。
3. 同一实体保持主图一致；替换主图后，检查首页、列表、详情与收藏快照中的展示效果。
4. 图片与内容无关或质量不达标时留空，由 CSS 抽象封面兜底，不要用无关图片凑数。
5. 收到权利人异议或下架请求时，及时在「内容管理」「基础资料」中移除或替换对应图片，并保留处理记录。
6. 图片政策只覆盖图像素材；标题、摘要与来源链接仍需遵守目标站点的转载规则，尽量使用摘要 + 原文链接。

## 接入方式

管理员可在后台上传图片，或填写公开可访问的图片 URL。上传图片写入 `MEDIA_DIR`（Docker Compose 使用命名卷 `xiwei_media`），前台通过 `/api/v1/media/<随机文件名>` 公开访问，无需登录。

随包图片放在 `frontend/public/media/`，构建后由静态服务直接提供。替换时保持文件名不变即可同时覆盖所有引用位置；也可以在后台重新上传，后台地址优先于迁移写入的默认值。建议同时记录：

- 素材来源与原链接；
- 使用位置（艺人、作品、角色、内容、事件或精选）；
- 替换与撤回流程。
